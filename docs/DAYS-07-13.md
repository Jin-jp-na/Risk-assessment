# RiskLens 2.0 — Days 7–13

## Implemented against the current Days 1–6 source

Day 7: independent Web scans, safe saved-result reopening, partial-result
display, and the existing Network/combined paths retained. The real loopback
integration test caught and fixed a Windows closed-socket error after reading a
complete HTTP body. Web-only assessment needs neither Nmap nor Gobuster.

Day 8: finalized jobs atomically save `backend/scans/snapshot_<id>.json` with
schema version, target identity, assessment timestamps, job/snapshot status,
per-component completion, hosts/ports/services/versions, normalized headers,
TLS details, paths, findings, original evidence, artifact names and SHA-256.
Components are `completed`, `partial`, `failed`, or `not_run`. Older scans are
normalized in memory on GET; GET does not write snapshots or start work. The
explicit offline migration below can persist those legacy snapshots.

Day 9: the new offline delta engine returns `added`, `removed`, `changed`, and
`uncertain`, with component, observation key, before/after and reason. No event
means “confirmed vulnerability” or “fixed”. Closed-port removals require
completed network coverage plus explicit closed evidence, or an up host with
matching scanned-port coverage and unambiguous, count-consistent closed
extraports. Filtered/down/missing/failed coverage remains uncertain. Service
identity changes involving unknown values are uncertain. Header comparisons
require complete HTTP evidence with the same response status and web origin;
TLS changes require verified coverage. Path absence needs completed scans with
the same exact wordlist and origin. Unknown legacy coverage stays uncertain.

Day 10: validated UUIDs and same-target identities; mismatched requested targets
or web scheme/IP/port return 409. The comparison endpoint only reads saved data.
Invalid UUID: 400; absent scan: 404; active scan/incompatible identities: 409;
corrupt/unsupported snapshot or artifact: 422. Incomplete terminal scans return
uncertainty rather than invented removals. Self-comparison is allowed.

Day 11: Compare Scans tab with baseline/current selectors, categorized
before/after tables, loading/empty/error states and comparison export buttons.
Network, Web, history and reporting remain. Removed runtime CDN dependencies;
local CSS and a native SVG evidence graph keep the UI offline. Restoring a scan
loads saved snapshots/results instead of trusting cached rendered HTML.

Day 12: frontend findings, Web findings, PDF and CSV use the snapshot's persisted
finding list. PDF includes target, timestamp, component coverage, separate
Network/Web findings, severity, confidence, evidence and remediation/re-test.
CSV includes the same findings plus target/timestamp and optional differences.
Unverified CVE candidates retain their conservative labels and confidence.

Day 13: regression tests for normalization, deltas, invalid/missing/partial
scans, read-only routes, independent Web operation, HTTP/TLS behavior, frontend
comparison states and export consistency; a real owned-loopback HTTP demo test.

## API essentials

```text
POST /scan                  Existing Network or combined API
POST /webscan               Independent Web; {url, authorized, path_discovery:false}
GET  /scans/history          Existing history
GET  /scans/{id}/snapshot    Saved snapshot, or read-only legacy normalization
GET  /scans/{new_id}/compare/{old_id}
GET  /scan/{id}/findings     Shared persisted Network + Web findings
GET  /webscan/{id}/findings  Shared persisted Web findings
GET  /scan/{id}/report.pdf?baseline={optional_old_id}
GET  /scan/{id}/findings.csv?baseline={optional_old_id}
```

Essential new request field, preserving old combined behavior:

```json
{"target":"http://127.0.0.1:8080","profile":"web","authorized":true,"network_scan":false,"path_discovery":false}
```

Authorization and the current operator's IP/port allowlists remain mandatory
for all new scans. No redirects, insecure certificate retry, credential guessing
or exploitation. Gobuster remains opt-in with one worker, delay, bounded input,
deadline and stop handling from Day 6. Compare/reopen/report requests do no active
assessment and do not require the old target to remain in the current scope.

## Safe localhost demo: baseline, change, rescan, compare, export

With the backend running, start the owned fixture in terminal 2:

```powershell
Set-Location 'D:\security project'
New-Item -ItemType Directory -Force .\artifacts | Out-Null
'{"nosniff":false}' | Set-Content -Encoding utf8 .\artifacts\lab-state.json
& '.\.venv-baseline\Scripts\python.exe' -m scripts.local_lab --port 8080 --state .\artifacts\lab-state.json
```

In terminal 3:

```powershell
Set-Location 'D:\security project'
$api = 'http://127.0.0.1:8787'
Invoke-RestMethod "$api/health"
function New-LocalWebAssessment {
    $body = @{url='http://127.0.0.1:8080'; authorized=$true; path_discovery=$false} | ConvertTo-Json
    $job = Invoke-RestMethod -Method Post "$api/webscan" -ContentType 'application/json' -Body $body
    $deadline = (Get-Date).AddSeconds(60)
    do {
        Start-Sleep -Milliseconds 500
        $status = Invoke-RestMethod "$api/scan/$($job.scan_id)"
    } while ($status.status -in @('pending','running','nmap_done') -and (Get-Date) -lt $deadline)
    if ($status.status -ne 'completed') { throw "Local assessment did not complete: $($status.message)" }
    return $job.scan_id
}
$oldId = New-LocalWebAssessment
'{"nosniff":true}' | Set-Content -Encoding utf8 .\artifacts\lab-state.json
$newId = New-LocalWebAssessment
$comparison = Invoke-RestMethod "$api/scans/$newId/compare/$oldId"
$comparison | ConvertTo-Json -Depth 20
Invoke-WebRequest "$api/scan/$newId/report.pdf?baseline=$oldId" -OutFile .\artifacts\localhost-comparison.pdf
Invoke-WebRequest "$api/scan/$newId/findings.csv?baseline=$oldId" -OutFile .\artifacts\localhost-comparison.csv
```

Expected: HTTP 200 in both snapshots, Network/paths `not_run`, HTTP `completed`.
The comparison has an `added` HTTP `security_header` entry with key
`x-content-type-options`, before null, after `nosniff`. Baseline finding
`WEB-HDR-003` is absent from the new persisted finding list; other missing-header
observations remain. Unassessed Network/TLS/path components remain uncertain,
never “fixed”. Open the local UI, choose Compare Scans and select those IDs to
see the same differences. Reopen each history entry without new target requests.
PDF/CSV contain the current saved findings and those differences. Stop both
servers with Ctrl+C when done.

## Remaining limits

The native offline graph uses a static SVG layout rather than the previous CDN
physics layout. Full browser layout/accessibility has not been exhaustively
tested; frontend handlers are exercised with Node. No live Nmap/Gobuster or
real-certificate scan was run during this implementation; those workers retain
their mocked regression coverage and need installed Windows binaries for a live
network demo. Snapshots use local JSON and one backend process; there is no
multi-process storage coordination. Evidence hashes support inspection, not
tamper-proof signing. Very large artifacts are bounded and can be rejected.
Legacy missing timestamps/coverage/wordlists cannot be invented. TLS/headers
retain Day 5's inactivity/slow-header limits. Deltas compare observations rather
than confirming product identity, exploitability or remediation.
